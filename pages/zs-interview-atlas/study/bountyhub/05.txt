QUESTION
How does the Redis Streams worker handle a Mongo update failure, and what does recovery really mean?

WHY THIS QUESTION MATTERS
Tests the implementation boundary, failure modes, and whether I can separate code evidence from assumptions.

CONTEXT
Redis Streams separates delivery from acknowledgment. A message that was delivered but not XACKed is pending; it is not automatically reclaimed merely because a process restarts and reads new entries.

TERMS
consumer group: Redis Stream consumers that share work and track acknowledgments.
pending entry: Delivered message not yet acknowledged by its group.
XACK: Redis command that marks a group message processed.

MECHANISM
1. Distinguish new-entry reads using `>` from old pending entries owned by a consumer.
2. Inspect the error branch and prove whether XACK is skipped after a failed Mongo write.
3. Add a bounded reclaim pass for idle pending entries and metrics for attempts and age.
4. Make projection writes replay-safe, and separately handle primary-replica lag or poison messages.

TECHNICAL EXPLANATION
XREADGROUP with `>` reads entries never delivered to the group; failed work is pending under its consumer. Restart plus `>` does not itself prove old pending work is reclaimed. Recovery should inspect pending entries, claim sufficiently idle ones, and track poison-message attempts. Upsert keyed by bounty/university can make repeated projection writes converge, but event ordering and deletes still need analysis. API also imports syncWorker while Compose starts a worker, so ownership and rebuild behavior deserve review. A failed process may leave an entry pending under its old consumer. A reclaim loop should use an idle threshold above normal high-percentile processing time, then claim in bounded batches. Reclaim can duplicate work if the old worker resumes, so projection updates need idempotency and version ordering. Also note `fetchBounty` reads via the replica: a temporarily missing row can return normally and then be XACKed, losing the refresh unless a retry or reconciliation path exists.
