A6

Physical design and the routing problem

Routing connects the pins of every net with wires on stacked metal layers so nothing shorts, every design rule holds, and wirelength, vias and congestion stay low. Read this module first.

Routing is the stage after placement. The two flows you should be able to name:

RTL›Synthesis›Netlist›Floorplan›Placement›Clock tree›Global routing›Detailed routing›Signoff (DRC, LVS, timing)

Digital flow above. The custom and memory flow (the one in Micron’s Hyderabad layout postings) looks like this:

Schematic›Layout in an editor such as Virtuoso›Wiring and routing›DRC and LVS (Calibre)›Parasitic extraction›Post-layout simulation
Net, pin. A net is a set of pins that must be connected. A 2-pin net needs a path, a multi-pin net needs a tree.
Metal layers. M1, M2, … stacked wiring layers. Each has a preferred direction, alternating horizontal and vertical.
Via. A vertical connection between adjacent layers. It adds resistance and area, so routers penalise it.
Track, pitch. Tracks are the legal lines for wires. Pitch is the distance between neighbouring tracks.
G-cell. A rectangular chip region used as one vertex in global routing.
Capacity, demand. How many wires can cross a G-cell boundary, and how many want to.
Overflow. max(0, demand − capacity) on an edge. Total overflow is the standard congestion measure.
Design rules, DRC. Manufacturing limits (width, spacing, area, via enclosure). DRC checks them. A violation is a DRV.
LVS. Layout versus schematic: does the drawn layout implement the same circuit as the netlist.
Parasitics. Unwanted wire resistance and capacitance. They decide delay, noise and power.
PPA. Power, performance (timing), area. Every design decision trades these off.
Slack. Required arrival time minus actual arrival time. Negative slack is a timing violation.
  • Input: a grid graph G = (V, E). Each vertex is a G-cell (per layer in 3D). Each edge joins adjacent cells and has a capacity. A set of nets, each a set of pins mapped to G-cells.
  • Output: for each net, a tree in G that connects all its pins.
  • Objective: minimise a weighted sum of wirelength, via count and total overflow.
  • Hardness: NP-hard. One multi-pin net alone is the Steiner tree problem. Many 2-pin nets under capacities contain the edge-disjoint paths problem.

Detailed routing then works on a far finer 3D grid of track intersections. It takes each net’s global route as a guide and must produce exact wires and vias with zero shorts and zero rule violations. Only after that does it minimise wirelength and vias.

Why two stages? A chip has millions of nets and billions of track points. Global routing plans coarse corridors on a small graph so congestion is spread out. Detailed routing then solves many small local problems inside those corridors.

A 5×5 grid of G-cells, every edge has capacity 1. Net A runs from (0,2) to (4,2). Net C runs from (1,2) to (3,2). Choose how C is routed:

The router paid 2 extra units of wire to remove 2 units of overflow. Two nets crossing inside a G-cell is not a conflict in global routing: they conflict only when they want the same edge beyond its capacity.

  1. Nets compete for shared capacity, so the best path for one net depends on all the others.
  2. Sequential routing is order-dependent: early nets block late nets (you will see this in A7).
  3. Design rules make “is this wire legal” depend on nearby shapes, not only on the cell itself.
  4. Objectives conflict: the shortest wire may cross a congested region or use too many vias.
Micron angle. Micron’s Hyderabad layout postings describe full-custom DRAM and LPDDR layout: bit cells, pitch matching, decoders, Calibre DRC and LVS. Inference: in a memory chip the cell array is extremely regular, and the circuits around it must fit the array’s pitch. Sensitive signals also need matched or symmetric wiring. So routing quality here includes constraint satisfaction, not only short wires.

A1

Graphs, and grids as graphs

A routing region is a graph you never store explicitly: cells are vertices, legal moves are edges, and the edge weight encodes everything the router cares about.

  • Adjacency list: O(V + E) memory, iterate neighbours in O(degree). Right for sparse graphs, which is almost everything in routing.
  • Adjacency matrix: O(V²) memory, O(1) edge lookup. Only for small dense graphs.
  • Implicit grid graph: a vertex is (x, y, layer). Neighbours are computed on the fly, so the graph costs no memory beyond per-cell arrays (cost, occupancy, blocked).

Layer 0 routes horizontally, layer 1 routes vertically (preferred direction). Tap any vertex to see its legal moves: wire steps along the layer’s direction, and a via to the other layer.

A 1000×1000 grid with 6 layers has 6 million vertices. With strict preferred directions each layer has about 1 million wire edges (999 × 1000), so about 6 million wire edges, plus 5 million via edges between the 6 layers. About 11 million edges for 6 million vertices: very sparse, and trivially generated on demand.

Keep per-cell data in flat arrays indexed by (z·H + y)·W + x (NumPy in Python), not in a dictionary keyed by tuples.

BlockageRemove the vertex, or give it infinite cost

ViaEdge between (x, y, z) and (x, y, z±1) with its own cost

def neighbours3d(x, y, z, W, H, L, blocked):
    # even layers route horizontally, odd layers vertically
    steps = [(1, 0, 0), (-1, 0, 0)] if z % 2 == 0 else [(0, 1, 0), (0, -1, 0)]
    steps += [(0, 0, 1), (0, 0, -1)]              # vias up and down
    for dx, dy, dz in steps:
        n = (x + dx, y + dy, z + dz)
        if 0 <= n[0] < W and 0 <= n[1] < H and 0 <= n[2] < L and n not in blocked:
            yield n

A2

BFS and DFS, and Lee’s maze router

BFS explores in rings of equal distance, so on an unweighted grid the first time it touches the target it has found a shortest path. That is Lee’s maze routing algorithm.

  • BFS: queue, O(V + E) time, O(V) memory. Shortest path in number of edges.
  • DFS: stack or recursion, O(V + E). Not shortest. Used for connectivity, cycle detection, topological order.
  • Lee’s algorithm (1961) has two phases: wave expansion (BFS labels each cell with its distance from the source) and backtrace (walk from the target to any neighbour with a label one smaller, until you reach the source).
  • It finds a path if one exists, and the path is shortest. The weakness: time and memory grow with the whole area searched, for every net.

Press ▶ to dequeue one cell at a time. Blue cells are labelled with their distance from S. Amber cells are in the queue. When T is dequeued, the green backtrace appears. Tap cells to add or remove walls.

On the default grid, T gets label 8. The straight-line (Manhattan) distance is 4. The wall forces 2 steps away from the target and each must be undone: 4 + 2·2 = 8. BFS had to label every cell closer than 8 before it reached T. Remember how many that was, because A4 beats it.

from collections import deque

def neighbours(grid, x, y):
    for dx, dy in ((1, 0), (-1, 0), (0, 1), (0, -1)):
        nx, ny = x + dx, y + dy
        if 0 <= ny < len(grid) and 0 <= nx < len(grid[0]) and grid[ny][nx] != "#":
            yield nx, ny

def lee_route(grid, src, dst):
    """Lee's maze router = BFS wave expansion + backtrace. O(W*H) time and memory."""
    parent = {src: None}
    queue = deque([src])
    while queue:
        cell = queue.popleft()
        if cell == dst:                       # backtrace phase
            path = []
            while cell is not None:
                path.append(cell)
                cell = parent[cell]
            return path[::-1]
        for nxt in neighbours(grid, *cell):
            if nxt not in parent:             # label each cell once
                parent[nxt] = cell
                queue.append(nxt)
    return None                               # no path exists
  • Multi-pin nets: connect two pins, then run a multi-source BFS that starts from every cell of the partial tree and stops at the nearest unconnected pin. Repeat. This gives a valid tree, not the minimum one (A5).
  • Memory trick from Lee’s paper: a repeating label pattern (Akers’ 1, 1, 2, 2) needs only two bits per cell.
  • Fixes for scale: a bounding box around the pins, A* to steer the wave (A4), searching from both ends, global routing first so detailed search stays inside a narrow guide, and cheap pattern routes where no search is needed (A7).
Micron angle. BFS on a grid is the first thing a routing team can ask you to code. The follow-ups are predictable: “what if moves have different costs” (A3), “how do you make it faster” (A4), “what about a five-pin net” (A5), “what about the second net” (A7).

Weighted shortest paths: Dijkstra, Bellman-Ford, DAGs

Once moves have different costs (a via costs more than a wire step, a congested cell costs more than a free one), BFS is wrong and Dijkstra is the default.

Routing costs (wire, via, wrong-way, congestion) are all non-negative, so Dijkstra applies. “Uniform-cost search” in AI textbooks is Dijkstra.

One net, two candidate routes. Route 1 stays on the layer and goes around a blockage: 7 wire steps, 0 vias. Route 2 goes up through a via, runs 3 steps, and comes back down: 3 wire steps, 2 vias. Move the slider.

BFS counts hops, so it would always pick Route 2 (5 hops against 7). The right answer depends on the cost model, and the cost model is a design decision you tune.

Press Next on the widget. Each pop is final (its distance can no longer improve). Stale heap entries are skipped: Python’s heapq has no decrease-key, so you push a duplicate with the better distance instead.

import heapq

def dijkstra(adj, src):
    """adj[u] = [(v, w), ...] with w >= 0. Returns dist dict. O((V+E) log V)."""
    dist = {src: 0}
    heap = [(0, src)]
    while heap:
        d, u = heapq.heappop(heap)
        if d > dist[u]:                       # stale entry (lazy deletion)
            continue
        for v, w in adj[u]:
            nd = d + w
            if nd < dist.get(v, float("inf")):
                dist[v] = nd
                heapq.heappush(heap, (nd, v))
    return dist

Dijkstra finalises a vertex when popped, assuming nothing cheaper can appear later. Example: A→B costs 2, A→C costs 3, C→B costs −2. Dijkstra finalises B at 2, but the true shortest is A→C→B = 1.

dist[src] = 0, all others infinity
repeat V - 1 times:
    for every edge (u, v, w):  dist[v] = min(dist[v], dist[u] + w)
one more pass: if any dist still improves, there is a negative cycle
  • Router cost: cost = wire + via penalty + wrong-way penalty + congestion penalty (+ a timing weight for critical nets). “How would you make the router avoid congestion” is answered by changing weights, not the algorithm (A7).
  • Timing analysis is a longest-path computation on a DAG: process gates in topological order, arrival = max over inputs of (arrival + delay), slack = required − arrival. This is the “timing” in the JD’s “congestion, timing, power, or area trade-offs”.

A4

A* search and heuristics

A* is Dijkstra with a compass: it orders the frontier by f = g + h, where g is the cost so far and h estimates the cost still to go, so it searches toward the target instead of in all directions.

  • f(n) = g(n) + h(n). g is the exact cost from the source. h is the estimate to the target.
  • h = 0 gives Dijkstra: optimal, but explores in all directions.
  • Ordering by h alone gives greedy best-first search: fast, not optimal.
  • A* expands every vertex with f < C*, where C* is the optimal cost. A better heuristic means fewer such vertices.
  • Admissible: h never overestimates. h(n) ≤ true remaining cost. Gives an optimal path.
  • Consistent: h(n) ≤ cost(n, n′) + h(n′) for every edge (the triangle inequality). Implies admissible, and guarantees each vertex is expanded at most once, so a simple closed set is safe.
  • Manhattan distance |dx| + |dy| is admissible and consistent on a 4-connected grid when every step costs at least 1: one step changes it by at most 1.
  • Congestion penalties only add cost, so Manhattan stays admissible. It stops being admissible if some step can cost less than 1 per unit of distance. Fix: multiply h by the smallest per-step cost.
  • In 3D, add (minimum via cost) × |dz| as long as that is a true lower bound.

On the default grid, A* expands far fewer cells than BFS or Dijkstra and still finds the same length-8 path. Why: cells 1 and 2 have f = 4, cells 3 to 7 have f = 6, and all of those (f < 8) must be expanded. Then tie-breaking walks straight along the cells with f = 8 to the target. Check one: cell 8 is (2,1), g = 3, h = |5−2| + |3−1| = 5, f = 8.

  • Weighted A*: f = g + w·h with w > 1. Fewer expansions. The path costs at most w times the optimum. Use it when runtime matters more than the last few percent of wirelength, for example in early rip-up iterations. Try the weight selector in the widget above.
  • Tie-breaking: grids have many equal-f paths. Prefer the entry with larger g (deeper), so you do not expand a whole diamond of ties.
  • Memory: bounding box, bidirectional search, or IDA* (O(depth) memory, repeated depth-limited passes).
import heapq

def astar_route(grid, src, dst):
    """A* with Manhattan heuristic on a unit-cost grid. Returns (path, cells expanded)."""
    h = lambda c: abs(c[0] - dst[0]) + abs(c[1] - dst[1])
    g = {src: 0}
    parent = {src: None}
    heap = [(h(src), 0, src)]                 # (f, -g for tie-break, cell)
    closed = set()
    while heap:
        _, _, cell = heapq.heappop(heap)
        if cell in closed:
            continue
        closed.add(cell)
        if cell == dst:
            path = []
            while cell is not None:
                path.append(cell)
                cell = parent[cell]
            return path[::-1], len(closed)
        for nxt in neighbours(grid, *cell):
            ng = g[cell] + 1
            if ng < g.get(nxt, float("inf")):
                g[nxt] = ng
                parent[nxt] = cell
                heapq.heappush(heap, (ng + h(nxt), -ng, nxt))
    return None, len(closed)

Proof sketch (admissible h). Suppose A* pops a goal G2 with cost g(G2) > C*. Some vertex n on an optimal path is still on the frontier with its optimal g. Then f(n) = g(n) + h(n) ≤ g(n) + (true remaining cost) = C* < g(G2) = f(G2). So n would have been popped before G2. Contradiction.

A good line: “before proposing a learned method, I would implement the A* baseline with a clear cost function, because that is what the learned method has to beat on quality and runtime.”

A5

Spanning trees and Steiner trees

A net with more than two pins needs a tree, and the cheapest tree is usually not a spanning tree of the pins: adding extra branch points (Steiner points) saves wire.

  • MST over the pins (edge weight = Manhattan distance): easy. Prim O(n²) on the complete graph, or Kruskal O(E log E) with union-find.
  • Rectilinear Steiner minimal tree (RSMT): the shortest tree using horizontal and vertical segments, allowed to branch anywhere. NP-hard.
  • HPWL (half-perimeter wirelength): width + height of the pins’ bounding box. Exact for 2 and 3 pins, a lower bound otherwise. Placers use it because it is trivial to compute.
  • Hanan grid: draw a horizontal and a vertical line through every pin. An optimal RSMT exists using only the intersections of these lines, so the search space is finite: at most n² candidate Steiner points.
  • Bound: MST length ≤ 1.5 × RSMT length in the rectilinear plane. The plus-sign example above hits exactly 1.5. (On general graphs the MST-based bound is 2.)
  • FLUTE: a lookup-table method that returns optimal RSMTs for nets up to 9 pins very fast and splits larger nets. Widely used inside academic routers.
  • Net decomposition: global routers usually build an RSMT, split it into 2-pin segments, and route each segment (A7).
  • Timing: the minimum-wire tree can give a long driver-to-sink path. A shortest-path tree minimises each driver-to-sink length but uses more wire. Real tools blend the two (the Prim-Dijkstra trade-off).
def kruskal(n, edges):
    """edges = [(w, u, v)]. Returns (total weight, chosen edges). O(E log E)."""
    parent = list(range(n))
    def find(x):
        while parent[x] != x:
            parent[x] = parent[parent[x]]     # path compression
            x = parent[x]
        return x
    total, chosen = 0, []
    for w, u, v in sorted(edges):
        ru, rv = find(u), find(v)
        if ru != rv:                          # joins two components, no cycle
            parent[ru] = rv
            total += w
            chosen.append((u, v, w))
    return total, chosen

A7

How routers actually work

A router is a loop: decompose nets, route each one with a cheap pattern or a shortest-path search, find the conflicts, raise the cost of the contested resources, and reroute until the conflicts are gone.

MethodIdeaShortest?Cost
Lee (1961)BFS wave from the sourceYesO(W·H) time and memory
Hadlock (1977)Order by “detour number” (steps taken away from the target). Length = Manhattan distance + 2 × detoursYesFar fewer cells than Lee. Equivalent to A* with Manhattan
Soukup (1978)Run straight toward the target, fall back to BFS around obstaclesNot guaranteedFast in practice
Line search (Mikami-Tabuchi, Hightower)Store line segments instead of cellsNoVery low memory

Hadlock’s formula matches the A2 example: Manhattan distance 4, two detour steps, length 4 + 2·2 = 8.

Pattern routing. For a 2-pin connection, try fixed shapes before searching: an L-shape (one bend, two candidates) or a Z-shape (two bends). Evaluation is a handful of cost lookups. Routers use patterns for the first solution and keep maze routing for the nets that fail.

One layer, each cell holds one wire. Net A connects (1,0) to (3,0), net B connects (0,1) to (4,1), and there is a blockage at (2,0). Switch the routing order:

Common ordering heuristics: constrained or short nets first, nets with fewer alternatives first, timing-critical nets first. None is always right, which is why learning the order is an active research topic.

Route everything, find overflowed edges or shorts, remove (“rip up”) some of the nets involved, raise the cost there, and reroute them.

Weakness: the outcome still depends on which nets you rip up and in what order, and the loop can cycle between the same conflicting solutions.

Let nets overlap at first, but price the overlap. The cost of using resource n is:

c(n) = ( b(n) + h(n) ) × p(n)

  • b(n): base cost (wire length or delay).
  • p(n): present-sharing penalty. Grows with how many nets want n right now.
  • h(n): history. Rises after every iteration in which n was overused, and never resets.

Each iteration, every net is ripped up and rerouted by shortest path under the current costs. Stop when no resource is overused. History is needed because with only the present penalty, two nets can keep swapping between the same two contested resources forever.

Nets A and B both want resource M (capacity 1, base cost 1). A’s detour costs 3, B’s detour costs 5. Present factor 0.5 per unit of overuse (0 in iteration 1), history increment 0.6 per unit of overuse. Step through:

A, whose alternative was cheap, gave way. B, whose alternative was expensive, kept M. No ordering rule was needed.

  1. Build a Steiner tree per net and split it into 2-pin segments (A5).
  2. Initial routing with L and Z patterns, picking the cheapest under estimated congestion.
  3. Assign layers (often by dynamic programming over the tree).
  4. Iterate: find overflowed regions, rip up segments there, reroute with maze routing or A* under history-based costs.
  5. Stop at zero overflow or an iteration limit, then hand routing guides to the detailed router.

Names to know: FastRoute and NTHU-Route (global), CUGR and Dr.CU (CUHK), TritonRoute (the detailed router in OpenROAD), InstantGR (GPU global router).

Hardness and algorithm paradigms

Most routing problems are NP-hard, so the real skill is choosing between exact methods, approximation algorithms, heuristics and metaheuristics, and knowing which classical paradigm each building block uses.

  • P: solvable in polynomial time (shortest path, MST).
  • NP: a proposed solution can be checked in polynomial time.
  • NP-hard: at least as hard as every problem in NP. No polynomial algorithm is known.
  • NP-complete: NP-hard and in NP (decision problems).
  • Routing examples: minimum Steiner tree, routing many nets under capacities (edge-disjoint paths), optimal net ordering. All NP-hard.

These are the JD’s words, so keep the distinctions sharp.

ApproachGuaranteeExample in routing
Exact (ILP, branch and bound)Optimal, exponential worst caseILP on a small routing window
Approximation algorithmProven bound, polynomial timeMST as a 1.5-approximation of the Steiner tree
HeuristicNone, problem-specific ruleRoute short nets first. L-shape before maze
MetaheuristicNone, general search strategySimulated annealing, genetic algorithms, large neighbourhood search (B2)
Learned policyNone, learned from data or rewardRL for net ordering (B3)
  • Greedy: make the locally best choice and never undo it. Correct only with a proof (exchange argument). Dijkstra, Prim, Kruskal. Sequential net-by-net routing is greedy and not optimal.
  • Dynamic programming: optimal substructure plus overlapping subproblems. Bellman-Ford, Floyd-Warshall, knapsack, longest path in a DAG, layer assignment along a routing tree.
  • Backtracking: build step by step, undo when a constraint breaks. N-queens, constraint satisfaction.
  • Branch and bound: backtracking plus a bound that prunes branches which cannot beat the best so far. A* is best-first branch and bound with the heuristic as the bound.
  • Divide and conquer, hierarchy: global then detailed routing. Partition the chip into windows.

Capacity: 4 tracks. Pick nets to keep, maximising value. Greedy takes the best value-per-track first. Dynamic programming checks every capacity.

Micron angle. The JD line “compare solution quality, runtime, scalability, and robustness” is about exactly this trade-off. A complete answer to “how would you approach problem X” has this shape: formulate it as a graph or optimisation problem, state its complexity, build a simple baseline, solve small instances exactly for ground truth, then compare heuristics or learned methods against both.

Three likely openers

“Explain chip routing to a software engineer.”
“You have a 3D grid of wiring tracks and thousands to millions of nets, each a set of pins that must be connected. Every net needs a tree of wires. Wires of different nets cannot touch, and every wire must obey manufacturing rules. You want short wires, few vias and no congested regions. One net alone is a shortest-path or Steiner-tree problem. All nets together compete for the same space, which makes it NP-hard, so routers iterate: route, find conflicts, raise costs, reroute.”
“Two nets want the same track. What do you do?”
“If I route them one after another, the result depends on the order, and the second net may fail. A better approach is negotiated congestion: let both use the track at first, charge a cost that grows with present sharing and with the history of conflict on that track, and reroute both. The net that has a cheap alternative moves, the one that really needs the track keeps it.”
“Where does AI actually help in routing?”
“Mostly around the search core rather than replacing it. Predicting congestion or DRC hotspots before routing, learning decisions that are hand-tuned today such as net ordering, and searching tool parameters. End-to-end RL routers exist in papers but they are evaluated on small problems. So I would start from a classical baseline, add a learned component at one decision point, and measure wirelength, vias, violations and runtime against the baseline.”
